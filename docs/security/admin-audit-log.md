# Admin Audit Log

The admin audit log is available at `/tools/audit-logs` for operators reviewing governance and verification activity.

## Recorded actions

Security-relevant admin activity should be written through `frontend/lib/security/auditLogger.ts` with:

- actor: operator identifier or service account.
- category: admin, auth, contract, or system.
- action: concise action name such as approval, rejection, policy change, verification update, revocation, or deletion.
- severity: info, warning, or critical.
- details: entity identifiers, reason codes, or operational notes that do not expose secrets.
- timestamp and chain hash: generated by the logger for chronological review and tamper evidence.

## Review workflow

The audit viewer supports filtering by category, severity, and text search. Columns can be sorted by timestamp, actor, action, or severity. Critical entries and actions matching approval, rejection, policy, revocation, deletion, or verification updates are marked for operational review.

## Sensitive data

Do not place secrets, private keys, raw API keys, or hidden media metadata in audit details. Store stable identifiers, hashes, and short reason codes instead.
